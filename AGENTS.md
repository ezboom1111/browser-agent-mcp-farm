# Agent Context

This repository is a side project split out from a Japan travel planning
workspace. Treat this folder as the source of truth for the Browser-Agent MCP
Farm code. Do not assume the original travel workspace is present.

## Project Summary

Browser-Agent MCP Farm is a local Playwright BrowserContext farm exposed through
an MCP stdio server, a CLI, and a local HTTP queue. It is built for
evidence-first browser research: isolated leases, page capture, media artifact
capture, typed claim/citation gates, platform capability mapping, bounded
timestamped frame sampling, optional OCR, credentials-gated official API
metadata capture, source strategy planning, and browser-visible obstruction
classification.
It also includes configurable cautious browser overlay dismissal for ordinary
close/not-now and reject/necessary-only surfaces before evidence capture.
It also includes an information-source coverage registry for mapping search,
social, community, content, news, review, map/local, marketplace, knowledge DB,
messenger/private, recommendation, and AI-agent categories to locale-specific
platform coverage and support tiers.

Current package version and build/test status: see [`STATUS.md`](STATUS.md)
(generated by the verify gate; never restated here).

## Core Commands

```powershell
npm ci
npm run build
npm test
npm run test:ocr-integration
npm run test:official-api
npm run verify
node .\dist\cli.js evidence-run --url https://example.com/ --no-frames --wait-ms 0 --timeout-ms 10000
node .\dist\cli.js destination-recovery-plan --run-dir <evidence-run-dir> --format commands
node .\dist\cli.js auth-login --profile google-search-chrome --url https://accounts.google.com/ --persistent-profile --chrome
node .\dist\cli.js auth-cdp-import --profile google-search-cdp --cdp-url http://127.0.0.1:9222
node .\dist\cli.js serve-http --port 3333
node .\dist\cli.js register-all
```

`npm run verify` is the main local quality gate. It runs build, unit tests,
local smoke, public web smoke, media smoke, proxy smoke, and `npm audit`.
`npm run test:official-api` is an opt-in live API harness and only runs network
checks when `FARM_OFFICIAL_API_INTEGRATION=1` plus provider credentials are set.
Use `official-api-readiness --url <url>` before live checks to inspect
credential env references without calling provider APIs or printing tokens.
`npm run test:ocr-integration` is an opt-in OCR harness and only runs when
`FARM_OCR_INTEGRATION=1` and optional peer dependency `tesseract.js` is
installed. It renders local map-label, travel-price, coupon/discount, and
optional Korean/Japanese screenshots and checks OCR text-profile metadata.

## Engineering Principles

- Do not download or bypass raw platform video streams.
- Keep platform-specific logic outside `BrowserPool`.
- Claims must cite registered artifacts.
- Final reports must fail when there are zero claims or uncited claims.
- Distinguish confirmed transcript evidence, visual frame evidence, inferred
  observations, and unverified audio.
- Use browser-visible frame sampling for visual evidence.
- Preserve raw accessible artifacts and add structured derivatives when lawful
  and deterministic, such as WebVTT parsing.
- Keep all generated evidence run output out of git unless a small fixture is
  explicitly needed for tests.
- Official API clients must use explicit env var credential references and must
  not write raw token values into artifacts.

## Main Modules

- `src/browser-pool.ts`: Playwright context/page lifecycle, capture, actions,
  media indexing, cautious overlay dismissal, frame sampling entry point.
- `src/artifact-writer.ts`: artifact bundles, ledgers, media files, transcript
  derivatives, evidence kind inference.
- `src/evidence-runner.ts`: first-class workflow for platform capability,
  source strategy, capture, frame sampling, transcript/OCR-hit dense sampling,
  OCR, official API metadata, obstruction classification, assessment,
  claims/citations, and final claim gate.
- `src/source-strategy.ts`: generic source family strategy for search, maps,
  blogs, portal/news, travel booking, commerce, video/social, and generic web
  sources.
- `src/source-registry.ts`: information category, locale, top-slot, evidence
  role, and support-tier registry for source coverage planning.
- `src/source-navigation.ts`: typed portal-native navigation plans for search
  tabs, filters, map viewports, article/thread evidence, portal/news modules,
  travel/commerce offer and product states, video/social frames/OCR/
  obstructions, and generic web fallbacks.
- `src/source-navigation-execution.ts`: bounded execution-plan state model for
  safe navigation, including action caps, per-action timeouts, before/after
  capture flags, and unsupported action steps.
- `src/source-navigation-executor.ts`: browser-backed safe executor for
  explicit action-key recipes, before/after captures, action metadata
  artifacts, skipped-action records, unsupported-action records, expected
  visible-state assertions, and scoped locator captures.
- `src/client-state-destinations.ts`: shared client-state destination parser
  for Naver Place Apollo state, used by both read-only calibration and
  explicit source-navigation execution.
- `src/source-navigation-recipes.ts`: manual-only selector/action/capture-scope
  candidate planner for search, map, blog/forum, portal/news, travel/commerce,
  video/social, and generic web real-site calibration.
- `src/source-navigation-calibration.ts`: read-only selector calibration over
  manual-only recipe candidates, producing match/visibility/signal diagnostics.
- `src/source-navigation-recipe-catalog.ts`: explicit-opt-in recipe proposal
  catalog builder that classifies calibration-required, single-run-ready,
  manual-review, manual-value, blocked, and unsupported entries.
- `src/source-navigation-promotion.ts`: batch promotion and promotion-review
  helpers that write grouped catalog/export/actions files and classify which
  promoted action files are ready for evidence-run execution.
- `src/source-coverage-readiness.ts`: registry top-slot QA/QC audit that
  compares category/locale source slots with promotion summaries and emits
  calibration target lines for actionable not-ready slots.
- `src/source-coverage-calibration-loop.ts`: readiness-guided calibration loop
  planner for writing target files, calibration loop plans, promotion commands,
  coverage re-audit handoffs, and Markdown reports.
- `src/destination-recovery-plan.ts`: read-only consumer for completed

## Known Limitations

- Safe portal-native navigation is recipe-limited: the executor, explicit
  recipe input, expected-state assertions, scoped captures, and one-depth
  follow-ups exist, but broad maintained provider selectors and live defaults
  do not.
- Destination follow-up is provider-catalog-limited: bounded depth-1 triage
  and opt-in depth-2 exist, but not broad selectors for arbitrary live result
  cards or portal modules.
- Coverage registry top slots are planning seeds, not refreshed market-share
  claims. Bot-hostile categories (much of marketplace, parts of community,
  TikTok unattended) are official-API-only or human-headed-only, not
  autonomous coverage — see "Coverage Definition of Done and Freeze" in
  `docs/PRODUCT_DEVELOPMENT_PLAN.md`.
- OCR accuracy / non-English, scene-change thresholds, and real-account
  official API checks still need real-media / credentialed tuning.
- No published npm distribution and no production remote shared-server mode.

## Important Caveat

This project can honestly preserve and analyze browser-visible evidence, public
HTML/text, accessible media artifacts, WebVTT captions, sampled frames, optional
OCR text, and explicit-credential official API metadata. It must not claim full
video/audio understanding unless transcript/audio evidence is actually present
and cited.
